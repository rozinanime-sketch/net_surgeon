# net_surgeon

Консольная утилита для Linux, которая обходит блокировки сайтов провайдером (DPI).
Она сама подбирает рабочую технику обхода для каждого сайта: проверяет разные
техники пробами и выбирает по статистике, а не по одной случайной удаче.

## Возможности

- Обход блокировок по имени сайта (SNI): разбиение ClientHello на две
  TLS-записи, разрез по имени, disorder, OOB-байт.
- Автоподбор: выбранная техника запоминается, проверяется на реальных
  соединениях и перемеряется, если перестала работать.
- Прозрачный режим: перехватывает HTTPS, QUIC и DNS всей машины, поэтому
  браузер и приложения настраивать не нужно.
- Шифрованный DNS через встроенный DoH, чтобы провайдер не подменял ответы.
- ChatGPT, Claude, Gemini и другие нейросети, которые сами закрыты для
  России: их адреса узнаются через умный DNS (xbox-dns.ru), остальные сайты —
  через обычный DoH. Список — `smart_dns_domains.txt`.
- Обычный HTTP/HTTPS- и SOCKS5-прокси, если прозрачный режим не нужен.
- Терминальный интерфейс на русском и английском: диагностика, редактор
  доменов и настроек.
- Telegram там, где его адреса заблокированы целиком: соединения идут через
  ваш собственный бесплатный воркер на Cloudflare, см.
  [cloudflare/README.md](cloudflare/README.md).
- Приложение для Android: то же ядро через `VpnService`, без root. Сборка
  описана в [android/README.md](android/README.md).

Проверено на YouTube и Discord.

**Чего не умеет:** менять IP-адрес. Сервер видит ваш настоящий адрес, поэтому
если сервис сам отказывает по стране, утилита не поможет — тут нужен VPN.
Исключение — сервисы, для которых умный DNS держит свои серверы за границей
(см. `smart_dns_domains.txt`).

## Требования

- **Linux.**.
- **Для прозрачного режима:** `nft` (nftables), `iproute2`, `sudo` и `setcap`.
  Без `nft` программа перейдёт на старый путь через `iptables`.
  `setcap` входит в пакет `libcap` (Arch, CachyOS) или `libcap2-bin`
  (Debian, Ubuntu).
- **Для сборки из исходников:** Rust 2024
  (проще всего через [rustup](https://rustup.rs)). Для готовой сборки Rust
  не нужен.

## Установка

### Готовая сборка

Программа собрана статически и работает на любом дистрибутиве.

```sh
curl -LO https://github.com/rozinanime-sketch/net_surgeon/releases/download/v0.5.4/net_surgeon-0.5.4-x86_64-linux.tar.gz
tar xzf net_surgeon-0.5.4-x86_64-linux.tar.gz
cd net_surgeon-0.5.4
./run.sh
```

### Из исходников

```sh
git clone --branch v0.5.4 https://github.com/rozinanime-sketch/net_surgeon.git
cd net_surgeon
./run.sh
```

`run.sh` сам соберёт программу при первом запуске и пересоберёт, если код
изменился. Без `--branch v0.5.4` скачается текущая версия из `main`, а не релиз.

### Android

Скачайте `net_surgeon-0.5.4-arm64.apk` со [страницы релиза](https://github.com/rozinanime-sketch/net_surgeon/releases/tag/v0.5.4)
и откройте на телефоне. Android попросит разрешить установку из этого
источника — это нормально для приложений не из Google Play. Нужен Android 8
или новее и 64-битный процессор (arm64), то есть почти любой телефон последних
лет.

В приложении нажмите «Включить» и согласитесь на подключение VPN. Это не
настоящий VPN: трафик не уходит с телефона, подробнее — в
[android/README.md](android/README.md).

## Пример использования

1. Впишите сайты, которые нужно открыть, в `bypass_domains.txt`, по одному на
   строку. Поддомены учитываются: `youtube.com` покрывает и `m.youtube.com`.
2. Запустите утилиту:

   ```sh
   ./run.sh
   ```

   Скрипт попросит пароль `sudo`, чтобы включить перехват.
3. Откройте сайт в браузере как обычно. Если техники для него ещё нет,
   диагностика подберёт её сама в фоне.
4. Для выхода нажмите `q`. Перехват снимется, сеть вернётся как была.

> Если после выхода пропал интернет, выполните `./run.sh off`.
> Подробнее — в разделе [«Если что-то пошло не так»](#если-что-то-пошло-не-так).

### Другие режимы

```sh
./run.sh plain        # обычный режим: только прокси-порты, без iptables
./run.sh --diagnose   # только диагностика, трафик не меняется
./run.sh off          # аварийно снять перехват и вернуть сеть
./run.sh status       # показать, есть ли сейчас правила перехвата
```

В обычном режиме приложение нужно направить на прокси вручную:

| Что        | Адрес            |
|------------|------------------|
| HTTP/HTTPS | `127.0.0.1:1080` |
| SOCKS5     | `127.0.0.1:1081` |

### Файлы

- `bypass_domains.txt` — сайты, для которых включается обход.
- `config.toml` — настройки. У каждого параметра есть комментарий, но лучше
  не менять их, если не знаете, что делаете.
- `strategies.txt` — подобранные техники. Создаётся сам; удалите, чтобы всё
  перемерить с нуля.

## Если что-то пошло не так

### Пропал интернет

С `nft` такого быть не должно: правила перехвата лежат в таблице, которая
принадлежит процессу программы, и ядро удаляет её, как только процесс
завершился, даже после `kill -9` или падения.

На старом пути через `iptables` причина почти всегда одна: программа
завершилась, а правило перехвата осталось, и весь HTTPS уходит на порт,
где никто не слушает.

1. Проверьте, есть ли правила:

   ```sh
   ./run.sh status
   ```

2. Снимите их:

   ```sh
   ./run.sh off
   ```

   Команда снимает только свои правила (TCP, QUIC и DNS) и не трогает правила
   Docker и VPN.
3. Если `sudo` не пускает (не помните пароль, нет терминала), **перезагрузитесь**.
   Правила перехвата живут только в памяти ядра и после перезагрузки
   исчезают сами. Исключение — если вы сохранили их через `iptables-save`
   или сервис вроде `iptables.service`: не делайте этого, пока перехват
   включён.

Не используйте `iptables -F`: вместе с перехватом он снесёт правила Docker,
VPN и файрвола.

На пути через `iptables` до этого обычно тоже не доходит. При выходе скрипт
снимает перехват сам, а на случай `kill -9` или закрытого окна держит
сторожа — отдельный процесс от root, который снимает правила, как только
скрипт исчез. Если при выходе скрипт пишет «Нет прав sudo», правила снимет
сторож; проверьте это через `./run.sh status`.

### Интернет есть, но сайт не открывается

- **Включён VPN?** Скрипт предупреждает об этом при запуске. Через VPN
  провайдер трафик не видит, обход бесполезен, а диагностика записывает
  неверные техники.
- **Сайт есть в `bypass_domains.txt`?** Обход включается только для сайтов
  из списка. Добавить можно прямо в программе: меню «Домены».
- **Техника устарела.** Провайдер мог поменять фильтр. Запустите «Диагностику»
  для этого сайта или удалите `strategies.txt`, чтобы перемерить всё.
- **Сайт блокирует вас сам**, по стране. Это видно по странице с отказом
  от самого сервиса. Тут поможет только VPN.

### Предупреждения при запуске

| Сообщение | Что значит | Что делать |
|---|---|---|
| `TPROXY недоступен` | В ядре нет модуля `xt_TPROXY` | Ничего: QUIC пойдёт мимо обхода, браузер откатится на TCP |
| `Не удалось выдать полномочия` | Не сработал `setcap` | Поставьте `libcap` / `libcap2-bin` |
| `IPv6 не перехватывается` | Нет `ip6tables` или nat для IPv6 | Ничего: работает только по IPv4 |
| `не задан doh_bootstrap_ip` | Релей DNS не узнает адрес провайдера DoH | Впишите в `config.toml` IP-адрес сервера из `doh_provider`, пример есть в комментарии к параметру |
| `Не удалось запустить сторожа` | Нет `setsid` | Перехват снимется при обычном выходе; после сбоя — `./run.sh off` |
